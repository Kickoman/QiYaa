# Телеметрия

Сборки QiYaa из [Releases](https://github.com/Kickoman/QiYaa/releases) отправляют анонимную
статистику использования и отчёты о падениях. По ним видно, на каких системах работает QiYaa, что
ломается и чем пользуются люди. Выключить это можно в меню (правый клик по любому окну) → снять
галочку «Адпраўляць ананімную статыстыку выкарыстання» / «Отправлять анонимную статистику
использования» / «Send anonymous usage statistics». После этого ничего больше не отправляется, а
то, что ещё не ушло, удаляется с диска.

Сборка из исходников по умолчанию телеметрии не содержит вовсе: ни кода, ни пункта меню. Включает
её параметр CMake `QIYAA_WITH_TELEMETRY=ON` (см. [building.md](building.md#параметры-cmake)).

## Что отправляется

Пакеты событий уходят на `https://qiyaa.kanstancin.net/api/telemetry`, на тот же сервер, где
живёт джем. Каждое событие подписано тремя значениями:

- **id машины** — хэш (HMAC-SHA256) системного id машины с ключом приложения. Системный id —
  `/etc/machine-id` на Linux, `MachineGuid` на Windows, `IOPlatformUUID` на macOS — сам с машины
  не уходит. По хэшу машины можно считать, но нельзя связать с другими программами;
- **id запуска** — случайный при каждом запуске;
- **версия QiYaa.**

| Событие | Когда | Что в нём |
|---|---|---|
| `start` | при запуске | ОС и её версия, ядро, архитектура, версия Qt, вид сборки (deb, AppImage, Windows, macOS), язык системы и интерфейса, масштаб, число экранов, скин (встроенный по имени или просто «свой»), визуализация, эквалайзер вкл/выкл, собран ли и открыт ли Milkdrop, собран ли джем, звуковая подсистема, есть ли вход в Яндекс Музыку, первый ли это запуск |
| `exit` | при обычном закрытии | сколько секунд работало, сколько треков началось, минуты музыки и Milkdrop, сколько было джемов |
| `crash` | при следующем запуске после падения | сигнал или код исключения и адреса в стеке (`QiYaa+0x4f2a10`), сколько работало до падения, тип необработанного исключения C++ |
| `unclean_exit` | при следующем запуске, если прошлый не закрылся и не упал: убит, выключили питание, завис | сколько работало |
| `error` | что-то не получилось | только категория: сеть, HTTP-код Яндекс Музыки, вход, скин, Milkdrop (нет OpenGL, старый OpenGL…), отказ сервера джема |
| `feature` | переключили Milkdrop, джем, скин, язык, эквалайзер, визуализацию | что и на что |

Не отправляются **никогда**: токен Яндекса, имя и id аккаунта, названия треков и исполнителей,
тексты поиска, пути к файлам, тексты ошибок, имя пользователя и компьютера, системный id машины.
Сервер принимает только поля из схемы ([spec/telemetry](../spec/telemetry/README.md)), пакет с
чем-то ещё отклоняется целиком.

## Как это устроено

События копятся в папке `telemetry/` рядом с `settings.ini` (не больше 500) и уходят пачками
при запуске, раз в 5 минут и при закрытии. Без сети они ждут следующего раза. Если QiYaa упала,
обработчик сбоя успевает записать сигнал и стек в файл, и его отправит следующий запуск.
Скриншоты (`--screenshot`) и тесты ничего не отправляют.

Для проверки сборки с телеметрией на своём сервере джема: `QIYAA_TELEMETRY_URL=http://…/api/telemetry`.
